## 1. Направление

Та же тема — **«Backstage»**: студия+сцена, corner marks, дуотон magenta/amber. На приложении это должно читаться ещё плотнее к реальности — экран как «модель-лист» или «полароид с рабочего стола мейкера», а не как обычный соцсетевой UI с круглыми аватарками и мягкими карточками.

Ключевое отличие от веба: на телефоне меньше места — дуотон-градиенты используются реже и меньше (иначе съедают контент на маленьком экране), но **corner marks остаются** как главный узнаваемый элемент — они дешёвы по месту (тонкие штрихи по углам) и хорошо работают даже на маленьких превью.

## 2. Токены — перенос с адаптацией

### Цвет (без изменений, те же значения из specWEBDizain.md §2)
`--ink #12101A` · `--stage #1D1A29` · `--paper #F2EEE9` · `--magenta #E5487A` · `--amber #F2A93B` · `--line #3A3550`

Добавляется один токен, специфичный для приложения:
| Токен | HEX | Роль |
|---|---|---|
| `--stage-elevated` | `#252131` | Карточки поверх карточек (например, деталь заказа поверх kanban) — на вебе такой глубины вложенности нет, на мобильном есть модалки поверх экранов |

Тёмная тема — единственная в MVP (см. specAPP.md §7), системная светлая тема не поддерживается.

### Типографика
Те же семейства (Syne / Space Grotesk / Space Mono), но шкала сжимается под мобильный экран:
| Роль | Веб | Приложение |
|---|---|---|
| Display (заголовок экрана) | 40–64px | 28–32px |
| Заголовок карточки | 20–28px | 18–20px |
| Body | 16px | 15–16px (минимум 15px — iOS/Android читаемость на маленьком экране) |
| Mono/utility (статусы, цены, дедлайны) | 12–14px | 12–13px |

### Touch-таргеты (специфика приложения, на вебе неактуально)
- Минимальный размер тап-зоны — 44×44pt (iOS HIG) / 48×48dp (Material) — применяется даже к мелким mono-бейджам статуса, если они тапаются
- Расстояние между соседними тапаемыми элементами — не менее 8px, чтобы не было промахов пальцем

### Layout
- Без 12-колоночной сетки веба — мобильный layout: одна колонка с горизонтальными паддингами 16px (компактно) / 20px (просторно, на больших телефонах и в модалках)
- Скругления — то же правило, что на вебе: 4px на мелких элементах (бейджи, поля ввода), 0px на фото и карточках-«кадрах»
- Безопасные зоны (notch, home indicator, статус-бар) учитываются во всех экранах — контент не заходит под системные элементы

### Сигнатурный элемент — corner marks
Переносится как есть: L-образные штрихи по углам фото/карточек, magenta = активно/открыто, amber = дедлайн/ожидание. На маленьких превью (миниатюры в ленте, тач-скролл) штрихи чуть толще (1.5px вместо 1px на вебе), чтобы не терялись при уменьшении.

## 3. Навигация (специфика приложения)

Вместо верхнего nav-бара сайта — **нижняя таб-навигация**, 4 таба + условный 5-й:
```
[ Лента ]  [ Explore ]  [ + Создать ]  [ Уведомления ]  [ Профиль ]
```
- «+ Создать» — не обычный таб, а выделенная кнопка по центру (billда/истории), с ассиметричной формой (тот самый corner-mark мотив как акцент на кнопке)
- Бейдж-точка amber на «Уведомления», если есть непрочитанные
- Если пользователь в роли мейкера — доступ к Maker Studio не отдельный таб, а свитчер сверху на табе «Профиль» (Профиль / Maker Studio), чтобы не плодить табы для роли, которая есть не у всех

## 4. Расположение по экранам

### 4.1 Онбординг
```
[ Экран 1: логотип ALTER, дуотон-фон (единственное место, где градиент занимает весь экран) ]
[ Экран 2: выбор роли(-ей) — карточки Косплеер / Мейкер / Фотограф, можно выбрать несколько ]
[ Экран 3: вход — email или Google/Apple ]
[ Экран 4 (опционально, можно пропустить): аватар + никнейм ]
```

### 4.2 Лента / Explore
```
[ Верх: поиск-строка (тап открывает полноэкранный поиск) ]
[ Чипы фильтров — горизонтальный скролл, sticky под поиском ]
[ Подборки блоками, mono-заголовками: "НОВЫЕ БИЛДЫ" и т.д. ]
[ Внутри блока — горизонтальный скролл карточек-кадров ]
[ Pull-to-refresh на весь экран ]
```

### 4.3 Профиль (свой/чужой)
```
[ Header: аватар (corner marks), имя, роли-бейджи, статус коммишена крупным mono-лейблом ]
[ Ряд иконок-ссылок (Patreon/принт-шоп/соцсети) — горизонтальный скролл при большом количестве ]
[ Таб-переключатель (внутриэкранный, не путать с нижней навигацией): Билды | Истории | О себе ]
[ Сетка билдов (2 колонки) или вертикальная лента историй ]
[ Плашка «Конвенты» ]
[ Если это чужой профиль с открытым коммишеном — sticky-кнопка снизу над таб-баром: «Запросить коммишен» ]
[ Если свой профиль и роль включает «мейкер» — свитчер вверху: Профиль / Maker Studio ]
```

### 4.4 Создание билда / истории
```
[ Шаг 1: выбор фото (камера/галерея, мультивыбор для билда) ]
[ Шаг 2: персонаж/франшиза (текстовое поле с автоподсказкой) ]
[ Шаг 3: теги соавторов — поиск по никнейму, добавление мейкера/фотографа ]
[ Шаг 4 (если есть теги): экран согласия — "Отправить запрос на подтверждение?" ]
[ Превью перед публикацией — карточка с corner marks, как она будет выглядеть в профиле ]
```

### 4.5 Запрос коммишена (wizard)
```
[ Полноэкранный wizard, прогресс-индикатор сверху (mono, "Шаг 2 из 5") ]
[ 1. Тип работы  2. Референсы (камера/галерея)  3. Замеры (шаблон-форма)
  4. Срок и бюджет  5. Условия — чекбокс подтверждения ]
[ Экран успеха: "Заявка №… отправлена", кнопка "Смотреть мои заявки" ]
```

### 4.6 Maker Studio (мобильная)
```
[ Верх: сводка mono-цифрами (в работе / просрочки / средний чек) — горизонтальный скролл если не помещается ]
[ Свайпаемые табы-колонки вместо kanban-доски: Новая · Обсуждение · В работе · Примерка · Готово · Отправлено ]
[ Карточка заказа внутри колонки: клиент, миниатюра, дедлайн (amber если близко), статус депозита ]
[ Свайп по карточке вправо = следующий статус (с подтверждением для необратимых переходов) ]
[ Тап по карточке → полноэкранная деталь: чек-лист (тапаемые чекбоксы), заметки, шаблон договора, кнопка "Отметить депозит оплаченным" ]
[ Отдельный таб внутри Maker Studio: Календарь загруженности ]
```

### 4.7 Уведомления
```
[ Список уведомлений, сгруппированный по дате (Сегодня / Ранее) ]
[ Каждое — иконка типа (заявка/депозит/дедлайн/согласие), mono-таймстамп, тап открывает нужный экран (deep link) ]
[ Непрочитанные — точка amber слева ]
```

## 5. Компоненты (сквозные, специфика приложения)

- **Нижний таб-бар**: stage-фон, активный таб — иконка + подпись magenta, неактивные — paper с пониженной непрозрачностью
- **Статус-бейдж**: тот же, что на вебе (mono, uppercase) — `ОТКРЫТО` / `ЗАКРЫТО` / `ЛИСТ ОЖИДАНИЯ`, но с увеличенной тап-зоной, если кликабелен
- **Карточка-кадр**: то же визуальное решение, что на вебе, адаптированная под 2-колоночную сетку в профиле и горизонтальный скролл в лентах
- **Свайп-действие** (только приложение): фон-подложка под карточкой при свайпе показывает следующий статус mono-текстом до отпускания пальца
- **Wizard-прогресс**: тонкая линия сверху экрана, mono подпись шага — переиспользуется в создании билда и запросе коммишена
- **Пустые состояния**: иллюстрация в стиле corner marks (рамка без содержимого) + короткий mono-текст + primary-кнопка действия

## 6. Доступность и адаптивность

- Динамический размер шрифта системы (iOS Dynamic Type / Android font scale) — учитывается, layout не ломается при увеличенном шрифте
- Контраст — то же требование AA, что на вебе
- `prefers-reduced-motion` эквивалент — уважаем системную настройку «уменьшить движение», свайпы/переходы без лишней анимации при этом флаге
- Все интерактивные элементы достижимы для VoiceOver/TalkBack (подписи, не только иконки)
- Безопасные зоны устройства (см. §2) — обязательны на каждом экране
