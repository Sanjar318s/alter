# ALTER — Спецификация веб-платформы (specWEB.md)

> Платформа для косплееров: профиль-хаб + управление коммишенами + учёт авторства/согласия + комьюнити-общение.
> Версия: v1.1 (позиционирование обновлено по specChat.md §9 — было согласовано отдельным шагом, теперь внесено).
> Порядок реализации: **сайт → потом приложение**.

---

## 1. Идея и позиционирование

**Проблема, которую решаем:** жизнь косплеера/мейкера размазана по 5–6 разным сервисам (Instagram/TikTok — охват, Patreon/Ko-fi — донаты, Etsy/PayPal — заказы, Discord — общение, Google Sheets — учёт заказов), ни один из которых не сделан именно под косплей. Instagram душит охваты и банит за «кожу»/косплей-контент.

**Позиционирование (обновлено, см. specChat.md §9):** ALTER — это **дом для косплей-комьюнити с полезными инструментами внутри**, а не просто набор инструментов, вокруг которого органически вырастает сообщество. Profile Hub и Maker Studio остаются входной точкой и причиной прийти в первый раз — но личные сообщения и тематические каналы (specChat.md) делают из этого место, где остаются и возвращаются, а не просто разово пользуются функцией.

**Стратегия входа (не «ещё одна соцсеть» с первого экрана):** заходим не с ленты и подписок, а с узкого инструмента, который даёт пользу одному человеку с первого дня, до появления сети:

1. **Maker Studio** — управление коммишенами (заказы, депозиты, дедлайны, статусы) для мейкеров/косплееров, которые шьют/делают реквизит на заказ. Самая денежная и самая болезненная точка — сейчас ведётся в блокнотах и переписке.
2. **Profile Hub** — «Linktree, который понимает косплей»: портфолио костюмов, статус коммишенов (открыт/закрыт), сторис/истории, ссылки на Patreon/принт-шоп, расписание конвентов.
3. **Credit & Consent** — правильные теги косплеер↔фотограф↔мейкер, цепочки авторства, явное согласие на публикацию фото.
4. **Общение (specChat.md)** — личные сообщения (растут с первого диалога, поверх профиля/заказов) и узкие тематические каналы (франшиза/конвент/город — не один общий чат на всех). Это то, что превращает разовых пользователей инструмента в комьюнити, которое возвращается.

Explore (лента-открытие) растёт органически поверх этих модулей — так обходится проблема «курицы и яйца»; но само удержание пользователей обеспечивают модули 1–4 вместе, не только 1–3, как было в предыдущей версии этого документа.

**Аудитория:** глобальная, не ограничена Узбекистаном; старт через существующие Telegram-каналы/комьюнити косплееров.

**Не входит в MVP (но держим в голове как ценности бренда / будущий roadmap):**
- Модерация харассмента как отдельный продукт (сложно решить чистым софтом)
- «Справедливая выдача» в ленте для мало- и непредставленных авторов — фича алгоритма, добавляется позже
- Маркетплейс костюмов/реквизита как отдельный раздел
- Календарь ивентов/конвентов как отдельный модуль (в MVP — только поле в профиле)
- Групповые ЛС, e2e-шифрование переписки, голос/видео в каналах — см. specChat.md §2.1, §4, §3.3

## 2. Технический стек

| Слой | Технология | Причина |
|---|---|---|
| Frontend/SSR | Next.js (App Router), деплой на **Vercel** | edge-рендеринг, ISR, нет лагов холодного старта |
| БД | **Turso** (libSQL/SQLite на edge) | низкая задержка, реплики близко к пользователю |
| ORM | Drizzle ORM | лёгкий, типобезопасный, дружит с Turso |
| Аутентификация | Auth.js (email + Google/Apple OAuth) | стандарт для Next.js |
| Хранение медиа | Vercel Blob или Cloudflare R2 + Vercel Image Optimization | быстрая раздача изображений |
| Стили | Tailwind CSS + дизайн-система ALTER | согласованность, скорость вёрстки |
| Real-time (уведомления, статусы заказов, сообщения) | Server-Sent Events / Pusher-совместимый сервис | один и тот же слой для заказов и для чата (specChat.md §6), без лишней инфраструктуры на старте |
| Аналитика | Vercel Analytics + событийная таблица в Turso | не нужен отдельный сервис на старте |

**Требования к производительности (без лагов и долгой загрузки):**
- LCP < 2.5с на 4G, TTFB < 200мс за счёт edge-функций и Turso-реплик
- Все изображения — WebP/AVIF, responsive `srcset`, lazy-load ниже фолда
- ISR (Incremental Static Regeneration) для профилей и публичных страниц коммишенов — отдаём статику, ревалидируем в фоне
- Пагинация/infinite scroll с курсорами (не OFFSET) в Explore, ленте историй и **в сообщениях/каналах** (specChat.md §6)
- Skeleton-состояния вместо спиннеров на всех списках

## 3. Функциональные модули (веб)

### 3.1. Landing (публичная посадочная страница)
- Хиро-блок с формулировкой ценности («один профиль вместо пяти сервисов» + «дом комьюнити»)
- Демонстрация профиля-хаба и Maker Studio (скриншоты/живой пример)
- Блок «для кого»: косплеер / мейкер / фотограф
- Соц-доказательства (после запуска — реальные профили/отзывы)
- CTA: «Создать профиль» / «Открыть Maker Studio»

### 3.2. Profile Hub (ядро продукта)
Публичная страница `/u/[username]`, доступна без регистрации.
- Аватар, никнейм, роли (косплеер / мейкер / фотограф — можно несколько)
- Статус коммишенов: открыты / закрыты / лист ожидания (виден сразу, без клика)
- Портфолио «билдов» (костюмов): фото, персонаж/франшиза, дата, теги соавторов
- Лента историй (коротких постов о процессе, аналог сторис/блога)
- Внешние ссылки: Patreon/Ko-fi, принт-шоп, Instagram/TikTok, Discord
- Блок «Конвенты» — где будет автор (текстовые записи, без отдельного календаря в MVP)
- Кнопка «Запросить коммишен» — ведёт на публичную страницу коммишена мейкера (3.4)
- Кнопка «Написать» — открывает ЛС (specChat.md §2.1), с учётом настройки приватности получателя
- Настройки приватности: кто может смотреть контакты, кто может писать в ЛС, скрытие статуса заказов

### 3.3. Explore / Discovery
- Не бесконечная лента, а курируемые подборки: «Новые билды», «Открытые коммишены», «По франшизе», «По персонажу»
- Фильтры: роль (мейкер/косплеер/фотограф), статус коммишена, франшиза, локация/страна
- Поиск по никнейму, персонажу, франшизе

### 3.4. Публичная страница коммишена + форма запроса
Публичная страница `/u/[username]/commission`
- Описание услуги мейкера, примеры работ, цены «от», сроки выполнения
- Форма запроса: тип работы, референсы (загрузка фото), замеры (по шаблону), желаемый срок, бюджет
- После отправки — заявка попадает в Maker Studio мейкера со статусом «Новая», а также автоматически создаётся диалог ЛС между заказчиком и мейкером (specChat.md §2.1) — обсуждение заказа идёт там же, не отдельным каналом

### 3.5. Maker Studio (дашборд мейкера — будущий платный флагман)
Приватная зона `/studio`
- Kanban-доска заказов: Новая заявка → Обсуждение → В работе → Примерка/правки → Готово → Отправлено
- Карточка заказа: клиент, референсы, замеры, дедлайн, депозит (сумма/статус оплаты), заметки, чек-лист этапов
- Простой шаблон договора/условий (текст, который клиент подтверждает при заявке)
- Календарь загруженности мейкера (сколько заказов в работе одновременно)
- Базовая аналитика: сколько заказов в месяц, средний чек, просрочки

### 3.6. Credit & Consent (сквозной механизм)
- При загрузке фото билда — обязательные поля: тег мейкера (если не сам шил), тег фотографа
- Согласие: фотограф может отметить фото как «требует подтверждения косплеера» — публикуется только после подтверждения
- Публичная цепочка авторства под каждым фото/постом (косплеер → мейкер → фотограф)

### 3.7. Истории/посты (контент профиля)
- Короткий формат: фото/видео + текст, привязка к конкретному «билду»
- Реакции и комментарии (упрощённые на старте — лайк + комментарий, без сложной социальной механики)

### 3.8. Общение — ЛС и тематические каналы
Полная спецификация — **specChat.md**. Кратко для этого документа:
- `/messages` — список диалогов (ЛС) слева, тред справа на десктопе; список → тред как отдельные экраны на мобильной ширине
- Тематические каналы (франшиза/конвент/город) — не выделены в отдельный URL-раздел в MVP, живут в том же `/messages` с переключателем ЛС/каналы
- Жалоба + блокировка обязательны с первого релиза (specChat.md §4) — не опциональная фича «на потом»

```
users            (id, email, username, role_flags, created_at)

build_photos     (id, build_id, image_url, maker_id?, photographer_id?, consent_status)
stories          (id, user_id, build_id?, text, media_url?, created_at)
commissions      (id, maker_id, title, description, price_from, turnaround_days, status)
commission_requests (id, commission_id, requester_user_id?, contact, references_json, measurements_json, status, created_at)
orders           (id, commission_request_id, maker_id, status, deposit_amount, deposit_paid, deadline)
credits          (id, target_type, target_id, credited_user_id, role, confirmed)
notifications    (id, user_id, type, payload_json, read, created_at)
subscriptions    (id, user_id, plan, status, started_at)  -- заложено заранее, выключено на старте

-- Общение (полная версия — specChat.md §5)
conversations         (id, type: 'dm' | 'channel', created_at)
conversation_members  (conversation_id, user_id, role: 'member' | 'moderator' | 'owner', joined_at, last_read_at)

channels              (id, conversation_id, kind: 'franchise' | 'convention' | 'location', title, related_franchise?, related_event_date?, archived)

blocks                (blocker_id, blocked_id, created_at)
```

## 5. Монетизация

**Бесплатно навсегда (крючок для привыкания и вирусности через шеринг ссылок):**
- Profile Hub, портфолио билдов, статус коммишенов, лента историй, теги/credit-система
- Личные сообщения и тематические каналы — **бесплатно без исключений** (specChat.md §7) — это ядро «дома», ограничивать подпиской нельзя

**Платно позже (архитектура готова с самого начала, но выключена на старте):**
- Maker Studio: доска заказов, депозиты, договор — расширенный тариф для мейкеров
- Расширенная аналитика заказов
- Кастомизация витрины/профиля (темы, брендинг для мейкера)

Таблица `subscriptions` и проверки прав уже закладываются в код (feature flag), но платёжный флоу не подключается до появления первых активных мейкеров.

## 6. Адаптивность

- Mobile-first вёрстка (косплей-контент смотрят в основном с телефона)
- Брейкпоинты: 375 / 768 / 1024 / 1440
- Kanban-доска Maker Studio на мобильном — превращается в свайпаемые колонки-табы
- Формы (запрос коммишена) — пошаговые (wizard) на мобильном, в один экран на десктопе
- `/messages` — список/тред как один экран на десктопе, как два отдельных экрана на мобильной ширине (specChat.md §2.3)

---

## 7. Риски и как их обходим

| Риск | Как обходим |
|---|---|
| «Курица и яйцо» — пустая платформа никому не нужна | Стартуем не с соцсети, а с полезного соло-инструмента (Maker Studio / Profile Hub) |
| Маленькая ниша, слабая монетизация | Платный слой нацелен на мейкеров (у них уже есть деньги от заказов), а не на всех подряд |
| Люди сидят в Telegram/Instagram | Не конкурируем за внимание, а закрываем то, чего там нет; запуск через существующие Telegram-комьюнити |
| Переделка архитектуры под подписки задним числом | Таблица subscriptions и права закладываются с v1, даже выключенные |
| Общение превращает продукт в «ещё одну соцсеть» без дифференциации | ЛС и каналы работают поверх профиля/заказов/тегов — контекст, которого нет у Discord/Telegram (specChat.md §8) |
