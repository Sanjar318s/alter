# ALTER — Спецификация общения (specChat.md)

> Дополнение к specWEB.md / specAPP.md.
> Смещение позиционирования: ALTER — не только набор инструментов (Profile Hub / Maker Studio), но и **отдельный дом для косплей-комьюнити**, где можно переписываться и разговаривать, а не только вести портфолио и заказы.
> Реализуется поверх той же схемы данных и того же real-time слоя (SSE/Pusher-совместимый сервис), что уже заложен в specWEB.md §2.

---

## 1. Зачем это и почему не «ещё один общий чат»

Сообщество косплееров сейчас разбросано по Discord/Telegram/Instagram — единого места нет. Цель — дать такое место. Но пустой общий чат на старте — тишина и мертвечина, потому это делится на два разных механизма с разной логикой роста:

1. **Личные сообщения (ЛС)** — растут естественно, поверх того, что уже есть: профиль, коммишены, теги соавторов. Не нужна «критическая масса», чтобы ЛС были полезны — они полезны с первого диалога.
2. **Групповые/тематические чаты** — растут только если узкие и привязанные к конкретному интересу (франшиза, конвент, город), а не один общий поток на всех пользователей платформы.

---

## 2. Личные сообщения (ЛС)

### 2.1 Логика
- Один диалог = два человека, без групп в MVP (групповые ЛС — не в первой версии)
- Написать может любой зарегистрированный пользователь, с настройкой приватности у получателя: «Все» / «Только те, с кем есть общий билд/заказ» / «Никто» (по умолчанию — «Все», можно ужесточить)
- Точки входа: кнопка «Написать» в профиле, автоматический диалог создаётся при заявке на коммишен (обсуждение заказа идёт тут же, не отдельным каналом)

### 2.2 Функционал
- Текст, фото (референсы, примерки), без видео в MVP
- Статус прочтения (галочки), индикатор «печатает…»
- Закреп/архивирование диалога, поиск по диалогам
- Кнопка «Пожаловаться» / «Заблокировать» в каждом диалоге — без этого ЛС открывать нельзя (см. §4)

### 2.3 Где это на экранах
- **Веб**: раздел `/messages` — список диалогов слева, тред справа (десктоп); на мобильной ширине — список → тред как отдельные экраны
- **Приложение**: новый таб нижней навигации — **«Чаты»** (список ЛС + тематические каналы в одном месте, с переключателем сверху)

---

## 3. Групповые/тематические чаты (комьюнити-каналы)

### 3.1 Логика
Не один общий чат ALTER, а **каналы по конкретному признаку**:
- По франшизе/фандому («Genshin Impact», «Naruto» и т.д.) — создаются автоматически при накоплении достаточного числа билдов по этой франшизе, либо вручную модератором/автором с определённым числом подписчиков
- По конвенту («Comic Con Ташкент 2026») — временные, привязаны к дате мероприятия, архивируются после
- По городу/стране — для локальной координации (кто где встречается, совместные фотосессии)

### 3.2 Функционал
- Текстовые сообщения, фото, закреплённые сообщения (правила канала, дата ивента)
- Роли: создатель/модератор канала может закреплять, удалять сообщения, банить участника из канала (не из платформы целиком)
- Список участников виден, можно перейти в профиль

### 3.3 Не входит в MVP
- Голосовые/видео-чаты
- Реакции-эмодзи на уровне Discord (богатая кастомизация)
- Роли/права сложнее «модератор/участник»

## 4. Модерация и безопасность (обязательно с первого дня, не «потом»)

Именно личное общение — то место, где реально происходит харассмент, о котором говорилось в самом начале анализа болей косплееров. Открывать ЛС/чаты без базовой защиты нельзя:

- **Жалоба + блокировка** — обязательна в каждом диалоге и канале с первого релиза, не опция «на будущее»
- **Rate-limit на первые сообщения** от новых аккаунтов — защита от спама/масс-рассылок незнакомцам
- **Automoderation базового уровня** — фильтр ссылок на подозрительные домены, повторяющийся спам-текст (простое правило, не ML-модель на старте)
- **Не e2e-шифрование в MVP** — сообщения должны быть доступны модерации по жалобе; это стоит явно писать в правилах, чтобы не создавать ложных ожиданий приватности
- Согласуется с `specModeration.md` и `specLegal.md`, которые уже описывают более общие правила контента — здесь это распространяется и на переписку

## 5. Модель данных (дополнение к схеме из specWEB.md §4)

```
conversations         (id, type: 'dm' | 'channel', created_at)
conversation_members  (conversation_id, user_id, role: 'member' | 'moderator' | 'owner', joined_at, last_read_at)
messages              (id, conversation_id, sender_id, text?, media_url?, created_at, deleted)
channels              (id, conversation_id, kind: 'franchise' | 'convention' | 'location', title, related_franchise?, related_event_date?, archived)
reports               (id, target_type: 'message' | 'user' | 'channel', target_id, reporter_id, reason, status, created_at)
blocks                (blocker_id, blocked_id, created_at)
```

Использует тот же `notifications` и `device_tokens`, что и остальная платформа — новое сообщение = запись в `notifications` + push.

## 6. Технически

- Тот же real-time слой (SSE/Pusher-совместимый), что уже заложен в specWEB.md §2 — не новая инфраструктура
- Пагинация сообщений курсорами (как в Explore/ленте — не OFFSET)
- Медиа в сообщениях — тот же Vercel Blob/R2-пайплайн, что и для билдов/историй
- На мобильном — офлайн-очередь исходящих сообщений (отправка при восстановлении сети), как уже описано для остального контента в specAPP.md §2

---

## 7. Монетизация

Чат и ЛС — **бесплатно навсегда**, без исключений. Это ядро «дома», а не платная фича — ограничивать его подпиской противоречит самой идее места для комьюнити.

---

## 8. Риски и как обходим

| Риск | Как обходим |
|---|---|
| Общий чат пустой, потому что размыт по всем пользователям сразу | Не делаем один общий чат — только узкие тематические каналы (франшиза/конвент/город) |
| Харассмент и спам в ЛС | Жалоба+блокировка и rate-limit для новых аккаунтов — обязательны с первого релиза, не опция |
| Chat превращает продукт обратно в «ещё одну соцсеть» без дифференциации | ЛС и каналы работают поверх профиля/заказов/тегов — это то, чего у Discord/Telegram нет: контекст (общий билд, общий заказ, общий фандом), а не чат в вакууме |
| Нагрузка на модерацию переписки | Базовая automoderation + понятный флоу жалоб, без обещания полной приватности (не e2e) |

## 9. Изменение позиционирования (влияет на specWEB.md / specAPP.md §1)

Старая формулировка: «инструмент, который решает конкретную боль, сообщество растёт органически поверх него».

Новая формулировка: ALTER — это **дом для косплей-комьюнити с полезными инструментами внутри**. Profile Hub и Maker Studio остаются входной точкой и причиной прийти в первый раз — но ЛС и тематические каналы делают из этого место, где остаются и возвращаются, а не просто разово пользуются функцией.

Это изменение стоит внести в §1 specWEB.md и specAPP.md отдельным шагом — пока не трогал сами файлы, чтобы не переписывать их без подтверждения.
