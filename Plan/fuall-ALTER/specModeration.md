# ALTER — Модерация и NSFW (specModeration.md)

> Косплей-контент системно страдает от избыточной цензуры на Instagram (бан за «кожу»,
> см. специфику проблемы в specWEB.md §1) — поэтому ALTER не копирует политику Instagram
> «ноль NSFW», а вводит явную, предсказуемую систему уровней + человеческую модерацию
> там, где автоматика ошибается дороже всего (несовершеннолетние, харассмент).

---

## 1. Уровни контента

| Уровень | Определение | Видимость |
|---|---|---|
| **General** | Обычный костюм, без спорных элементов | Публично всем, Explore, гостям |
| **Mature (не NSFW)** | Откровенные, но не сексуализированные костюмы (бои-стайл брони, купальники персонажей и т.п.) | Публично, но с блюр-превью в Explore до тапа/подтверждения возраста в настройках аккаунта |
| **Restricted (18+)** | Явно сексуализированный контент | Только для залогиненных пользователей с подтверждённым возрастом 18+ в настройках; не в Explore/поиске по умолчанию, только в собственном профиле автора с явным дисклеймером на входе |
| **Запрещено** | См. §4 | Удаляется, аккаунт — по эскалации |

Автор сам маркирует уровень при публикации (обязательное поле, не опциональное) —
неправильная маркировка (занижение уровня) — нарушение правил (specLegal.md §2.3),
основание для последующей ре-модерации контента этого автора.

## 2. Пайплайн модерации

```
Публикация → автоматическая проверка → (если чисто) публикуется сразу с заявленным уровнем
                                       → (если подозрительно) MODERATION_HOLD (см. specAPI.md §4),
                                         не публично, в очередь ручной модерации
```

**Автоматическая проверка** (на загрузке фото):
- Классификатор NSFW (сторонний API или self-hosted модель) — сверяет с заявленным автором
  уровнем; расхождение (автор поставил General, классификатор даёт Restricted) → в очередь
- Простая эвристика по тексту (описание, теги) на маты/харассмент-паттерны — не блокирует,
  но повышает приоритет ручной проверки

**Очередь ручной модерации** (MVP — сам фаундер/1-2 модератора, не команда):
- Приоритет: жалобы пользователей > расхождение классификатора > случайный сэмплинг
- SLA на решение — цель 24–48 часов на старте (открыто масштабируется по мере роста)
- Решение: одобрить как есть / понизить-повысить уровень / отклонить с причиной автору

## 3. Жалобы пользователей

- Кнопка «Пожаловаться» на любом фото/истории/профиле/сообщении в переписке заказа
- Категории: неверный уровень контента (NSFW не помечен), контент без согласия,
  харассмент/буллинг, кража работы (нарушение Credit & Consent), спам, подозрение на
  несовершеннолетнего в Restricted-контенте
- Жалоба на "несовершеннолетний в Restricted" — **всегда** приоритет №1, автоматический
  временный hold контента до решения (не ждём очереди)

## 4. Абсолютные запреты (не уровень, а немедленное удаление + эскалация)

- Любой сексуализированный контент с реальным или предполагаемым участием
  несовершеннолетнего — zero tolerance, немедленное скрытие + блокировка аккаунта +
  (в зависимости от юрисдикции и серьёзности) обязанность сообщить в соответствующие
  органы/NCMEC-подобные структуры — этот пункт **требует юридической консультации перед
  запуском**, здесь только продуктовый уровень процесса
- Контент без согласия изображённого человека при жалобе от этого человека — снимается
  сразу, разбор — постфактум
- Доксинг, угрозы, целенаправленный харассмент — снимается, эскалация к блокировке аккаунта

## 5. Что намеренно НЕ входит в MVP

Как зафиксировано в specWEB.md §1 «Не входит в MVP»: модерация харассмента как отдельный
продукт со сложной механикой (репутация, автоматическое выявление паттернов травли) —
на старте это ручной разбор жалоб, не отдельная система. «Справедливая выдача» в ленте
для непредставленных авторов — фича алгоритма Explore, добавляется позже, не часть
модерационного процесса.

## 6. Технически (связка с API/данными)

- Поле `moderation_status` (`clean` / `pending` / `held` / `rejected`) на `build_photos`,
  `stories` — используется для `MODERATION_HOLD` (specAPI.md §4)
- Отдельная таблица `reports` (`id, target_type, target_id, reporter_id, category, status, created_at`)
- Поле `content_level` (`general` / `mature` / `restricted`) на контенте — влияет на
  видимость в Explore/поиске согласно §1
- Настройка аккаунта `age_confirmed_18plus` (bool) — открывает Restricted-контент
